# راهنمای اونر VYRN

وضعیت تحویل، ۱۷ اکتبر ۲۰۲۶: Backend نسخهٔ `a05831a` و PostgreSQL روی سرور `217.18.90.114` فعال و سالم‌اند. اصلاح مجوزهای هم‌زمان و مسیر اتمی واکنش‌ها روی سرور فعال شده‌اند؛ اتصال رابط واکنش هنوز کامل نیست و کنترل آن در اپ غیرفعال است. HTTPS عمومی و پنل خصوصی بررسی شده‌اند. پنل مدیریت فقط با تونل SSH باز می‌شود. انتشار نهایی اپ هنوز کامل نیست؛ نسخهٔ Android فعلی Debug است.

## ۱. ورود امن از ویندوز

PowerShell را باز کنید و دستور زیر را اجرا کنید. این پنجره باید تا پایان استفاده از پنل باز بماند:

```powershell
cd C:\Users\PC\Documents\ChatGPT\Telegram\VYRN
ssh -i .local/ssh/vyrn_ed25519 -p 3939 -o IdentitiesOnly=yes -o UserKnownHostsFile=.local/known_hosts -o StrictHostKeyChecking=yes -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 -N -L 127.0.0.1:19091:127.0.0.1:19091 root@217.18.90.114
```

سپس در مرورگر همین کامپیوتر آدرس `http://127.0.0.1:19091/` را باز کنید. HTTP این آدرس فقط روی loopback است؛ مسیر تا سرور داخل SSH رمزگذاری می‌شود. با بستن SSH دسترسی قطع می‌شود. اگر پورت مشغول بود، احتمالاً تونل قبلی هنوز باز است. برای استفاده از پورت دیگری، بخش اول نگاشت را به `127.0.0.1:19092` تغییر دهید و آدرس مرورگر را هم عوض کنید.

کلید خصوصی در `.local/ssh/vyrn_ed25519` است؛ فایل `.pub` فقط بخش عمومی است. کلید خصوصی را داخل Git، VPS یا پیام‌رسان کپی نکنید. ورود SSH با این کلید آزمایش شده است؛ روش ورود قبلی سرور حفظ شده است.

## ۲. دریافت مشخصات حساب اونر

ایمیل حساب: `owner@vyrn.local`. رمز تصادفی و اطلاعات برنامه احراز هویت در فایل محافظت‌شده `/etc/vyrn/owner-access.json` روی سرور قرار دارند. مقدارهای آن در چت یا سورس قرار نگرفته‌اند.

برای مشاهده خصوصی در ترمینال خودتان:

```powershell
cd C:\Users\PC\Documents\ChatGPT\Telegram\VYRN
ssh -i .local/ssh/vyrn_ed25519 -p 3939 -o IdentitiesOnly=yes -o UserKnownHostsFile=.local/known_hosts -o StrictHostKeyChecking=yes root@217.18.90.114
```

بعد از ورود:

```sh
cat /etc/vyrn/owner-access.json
```

این خروجی محرمانه است؛ آن را برای کسی نفرستید و در عکس یا ضبط صفحه نشان ندهید. `password` رمز ورود است؛ `totp_secret` را به‌صورت دستی در برنامه Authenticator با نوع «زمان‌محور» ثبت کنید. اگر فایل حاوی `otpauth_uri` بود، می‌توانید آن را در برنامه‌ای که واردکردن این URI را پشتیبانی می‌کند وارد کنید. از سایت عمومی ساخت QR برای این مقدار استفاده نکنید. رمز و کلید احراز هویت را در مدیر رمز شخصی نگهداری کنید.

در پنل ابتدا ایمیل و رمز را وارد کنید، سپس کد شش‌رقمی Authenticator را بزنید. زمان گوشی باید خودکار باشد. اگر همان کد قبلاً مصرف شده، منتظر کد بعدی بمانید. تازه‌سازی صفحه ممکن است ورود مجدد بخواهد؛ نشست پنل در حافظه مرورگر نگهداری می‌شود.

## ۳. کارهایی که همین حالا در پنل می‌توانید انجام دهید

| بخش | اختیار فعلی اونر |
|---|---|
| نمای کلی | دیدن تعداد کاربران، نشست‌ها، گروه‌ها و حافظه مصرفی |
| کاربران ← مدیریت | مسدودکردن یا رفع مسدودی کاربر، تعیین رمز جدید، خروج همه نشست‌های او |
| دعوت‌ها | ساخت کد دعوت با تعداد استفاده و مدت اعتبار، لغو دعوت |
| گروه‌ها | مشاهده نام، تعداد اعضا و زمان ساخت گروه |
| گزارش فعالیت | مشاهده رخدادهای مدیریت و شناسه انجام‌دهنده و هدف |
| زبان | تغییر فارسی و انگلیسی |
| خروج | خاتمه نشست جاری پنل |

برای دعوت: بخش «دعوت‌ها» را باز کنید، تعداد استفاده و اعتبار به روز را وارد کنید و «ساخت دعوت» را بزنید. کد فقط همان بار نمایش داده می‌شود؛ آن را خصوصی به فرد موردنظر بدهید. لغو دعوت، استفاده بعدی از آن را متوقف می‌کند. دعوت اولیه bootstrap هم در فایل دسترسی اونر نگهداری می‌شود؛ برای استفاده روزمره دعوت‌های محدود جدید بسازید.

برای مدیریت کاربر: «کاربران» ← «مدیریت» ← عملیات موردنظر. خروج همه نشست‌ها یعنی کاربر باید دوباره وارد شود. بازنشانی رمز، رمز جدید را به کاربر اعلام می‌کند؛ پنل رمز قبلی او را نشان نمی‌دهد. برای حساب خودتان عملیات خروج نشست‌ها را فقط وقتی انجام دهید که رمز و Authenticator را در اختیار دارید.

پنل فعلی امکان خواندن متن پیام خصوصی رمزگذاری‌شده را ندارد. مدیریت دلخواه سهمیه‌ها، ساخت مدیران متعدد از رابط، حذف کامل گروه و تنظیم همه Feature Flagها هنوز از پنل پیاده‌سازی نشده‌اند. عددهای `config/project.yaml` به‌تنهایی همه تنظیمات runtime را تغییر نمی‌دهند.

## ۴. کاربران و اپ Android

پس از فعال‌شدن دامنه و HTTPS، ثبت‌نام با دعوت، ایمیل و رمز انجام می‌شود. این پروژه برای ثبت‌نام به شماره تلفن یا OTP ایمیلی متکی نیست. حداکثر دستگاه‌ها سه دستگاه برای هر کاربر است.

APKهای Debug در پوشه `artifacts` پروژه هستند؛ نسخهٔ جامع ARM حدود ۱۵۹ مگابایت و نسخهٔ ARM64 حدود ۱۲۲ مگابایت است. دامنه `https://api.vyrn.eclipseofficial.xyz` با گواهی معتبر فعال است؛ ورود، خروج و شمارش و صفحه‌بندی جست‌وجوی گروه از HTTPS عمومی آزمایش شده‌اند. اتصال کامل APK نصب‌شده به سرور تولید و همه جریان‌های اپ هنوز تست پذیرش نشده‌اند. انتشار Release، امضای نهایی و تست پذیرش عملی روی گوشی واقعی هنوز انجام نشده‌اند. فایل Keystore نهایی باید بیرون Git و VPS بماند.

برای جست‌وجوی متن سادهٔ گروه، داخل گروه منوی سه‌نقطه و سپس «جست‌وجو» را بزنید، عبارت را وارد کنید و دکمهٔ جست‌وجوی کیبورد را بزنید. شمارنده تعداد کل نتیجه‌ها را نشان می‌دهد و فلش‌های بعدی/قبلی بین آن‌ها حرکت می‌کنند. جست‌وجوی خصوصی روی دستگاه و جست‌وجوی جهانی/هشتگ هنوز آمادهٔ پذیرش نیستند؛ فیلتر فرستنده و تاریخ نیز فعلاً غیرفعال‌اند. یک گروه تست خالی به نام «تست جست‌وجوی Vyrn» در حساب آزمایشی برای بررسی اتصال باقی مانده است؛ پیام‌های موقت و نشست بررسی حذف شده‌اند.

تماس صوتی و تصویری خاموش‌اند تا UDP ورودی Provider و TURN آزمایش شوند. رابط کامل پیام خصوصی، رسانه، اعلان پس‌زمینه و آپدیت نهایی هنوز بخشی از کار باقی‌مانده پروژه‌اند. صفحه وب پنل، جایگزین اپ پیام‌رسان نیست.

## ۵. کنترل سلامت سرور

با SSH وارد شوید. برای کوتاه‌شدن دستورها این تابع را در همان نشست بسازید:

```sh
cd /opt/vyrn/current
dc() { docker compose --env-file /etc/vyrn/runtime.env -f deployment/compose.yaml -f deployment/compose.existing-nginx.yaml "$@"; }
dc ps
curl -fsS http://127.0.0.1:18080/health/ready
```

انتظار: دو سرویس `core` و `postgres` سالم و پاسخ `{"status":"ready"}`. دیتابیس پورت عمومی ندارد. Core فقط روی `127.0.0.1:18080` و پنل فقط روی `127.0.0.1:19091` گوش می‌دهند.

مشاهده لاگ و راه‌اندازی مجدد Core:

```sh
dc logs --tail 100 core
dc restart core
dc ps
curl -fsS http://127.0.0.1:18080/health/ready
df -h /
free -h
```

پیش از اشتراک لاگ، اطلاعات شخصی احتمالی را حذف کنید. از `docker compose config` بدون `-q` استفاده نکنید؛ خروجی کامل می‌تواند Secret نشان دهد. برای اعتبارسنجی فقط `dc config -q` کافی است.

Docker برای شروع خودکار فعال است و کانتینرها `unless-stopped` دارند. ریبوت کامل VPS هنوز آزمایش نشده است. سرویس‌های قبلی Nginx، TeamSpeak و دیگر سرویس‌های سرور حفظ شده‌اند؛ توقف کلی Docker یا Nginx می‌تواند سرویس‌های دیگر را هم تحت تأثیر قرار دهد.

## ۶. مسیرهای مهم

| مسیر روی سرور | کاربرد |
|---|---|
| `/opt/vyrn/current` | لینک نسخه فعال سورس و پنل |
| `/opt/vyrn/releases/vps-initial-20261004` | نسخه اولیه مستقرشده |
| `/etc/vyrn/runtime.env` | تنظیمات محرمانه runtime، دسترسی ۶۰۰ |
| `/etc/vyrn/owner-access.json` | رمز و TOTP اونر، دسترسی ۶۰۰ |
| `/etc/nginx/sites-available/vyrn-owner-tunnel` | تنظیم پنل خصوصی Nginx |
| Docker volumes | داده PostgreSQL و رسانه؛ با حذف Volume داده حذف می‌شود |

`docker compose down -v` برای کار روزمره ممنوع است؛ Volume و اطلاعات را حذف می‌کند. برای تغییر نسخه، ابتدا Backup و سازگاری migration را بررسی کنید. فقط تعویض فایل برنامه برای برگشت دیتابیس کافی نیست.

## ۷. Backup و Restore

مقصد خارجی هنوز تعیین نشده است؛ Backup خودکار خارجی فعال نیست. فایل روی همان VPS در خرابی دیسک یا حذف سرور قابل اتکا نیست. اسکریپت `scripts/backup.sh` برای Restic روی S3-compatible HTTPS آماده است و رمز رمزگذاری مستقل می‌خواهد. Credentialها فقط در `/etc/vyrn/backup.env` با دسترسی ۶۰۰ قرار می‌گیرند. نسخه دیگری از رمز رمزگذاری باید خارج VPS نگهداری شود.

بستهٔ نسخهٔ ۲ شامل dump دیتابیس، همهٔ رسانه‌ها و قطعه‌های آپلود، فهرست اندازه و SHA-256 آن‌ها، تنظیمات، شناسهٔ Image و در صورت وجود تنظیمات اونر و Nginx است. Core هنگام تهیهٔ dump و آرشیو رسانه متوقف می‌شود و سپس دوباره شروع می‌شود؛ هنگام خطای کپی نیز شروع مجدد تلاش می‌شود. در این بازه مهاجرت یا تغییر مستقیم دیتابیس اجرا نکنید. فضای موقت به‌اندازهٔ رسانه‌ها لازم است؛ وضعیت موفق فقط پس از بررسی فایل‌ها، آپلود و `restic check` ثبت می‌شود.

پس از آماده‌شدن مقصد و تنظیم امن متغیرهای Restic، نسخهٔ بازیابی را در پوشه‌ای خصوصی قرار دهید. `SNAPSHOT_ID` را از خروجی فهرست انتخاب کنید؛ مقادیر Credential را در دستور یا چت وارد نکنید:

```sh
restic snapshots --host vyrn --tag daily
read -r SNAPSHOT_ID
install -d -m 700 /var/lib/vyrn/restore-drill
restic restore "$SNAPSHOT_ID" --target /var/lib/vyrn/restore-drill
find /var/lib/vyrn/restore-drill -type f -name backup-format
```

پوشهٔ حاوی `backup-format` را به `scripts/restore-smoke.sh /path/to/restored/bundle` بدهید. این دستور دیتابیس جدا می‌سازد، dump را برمی‌گرداند، تطابق ردیف‌های رسانه و فایل‌های بازیابی‌شده را بررسی می‌کند و فضای آزمایش را پاک می‌کند؛ دیتابیس و رسانه‌های فعال جایگزین نمی‌شوند. dump قدیمی به‌تنهایی فقط آزمون دیتابیس است. بازیابی سرویس تولید باید با Image سازگار با نسخهٔ ثبت‌شده و پس از آزمون کامل انجام شود. بازیابی واقعی روی VPS در دیتابیس و volume جدا، همراه دو فایل رسانه/قطعهٔ موجود و راه‌اندازی Image جدید، انجام و بررسی شده است. این آزمون جایگزین بکاپ خارجی یا آزمون بازیابی از نابودی کامل سرور نیست؛ مقصد خارجی هنوز تعیین نشده است.

اسکریپت فعلی دیتابیس و تنظیمات را می‌گیرد؛ پوشش رسانه هنوز باید افزوده و Restore آن آزمایش شود. برای دستور Restore آزمایشی و محدودیت‌ها به `docs/BACKUP_RESTORE.md` مراجعه کنید. Restore تولید باید در دیتابیس و Volume جدا انجام شود، سپس پس از تست جابه‌جایی صورت گیرد.

برای یک dump موقت دیتابیس روی همین سرور، بعد از تعریف تابع `dc`:

```sh
umask 077
mkdir -p /var/backups/vyrn-temporary
dc exec -T postgres pg_dump -U vyrn -d vyrn -Fc > "/var/backups/vyrn-temporary/database-$(date -u +%Y%m%dT%H%M%SZ).dump"
```

این دستور رسانه را نمی‌گیرد و در استقرار اولیه اجرا نشده است. آن را Backup کامل حساب نکنید. dump محرمانه است و نباید داخل Git قرار بگیرد.

## ۸. وضعیت دامنه عمومی و مدیریت DNS

هر هشت رکورد DNS با IP سرور و حالت DNS-only ساخته شدند. API، WebSocket، رسانه و push پشت Nginx و HTTPS هستند؛ سالم‌بودن مسیرها به معنی تکمیل همه قابلیت‌های اپ نیست. گواهی هفت دامنه تا ۲ ژانویه ۲۰۲۷ معتبر است؛ تمدید آزمایشی و reload موفق بوده‌اند و `certbot.timer` فعال است. دامنه admin و وب و updates فعلاً پاسخ ۵۰۳ می‌دهند؛ پنل از تونل باز می‌شود. TURN فقط رکورد DNS دارد و سرویس تماس فعال نیست.

Token برای عملیات فقط در حافظه فرایند استفاده شد و در سرور، Git یا فایل ذخیره نشد. برای تغییرات بعدی DNS، دو متغیر `CLOUDFLARE_API_TOKEN` و `CLOUDFLARE_ZONE_ID` را امن تنظیم کنید:

```powershell
cd C:\Users\PC\Documents\ChatGPT\Telegram\VYRN
. ./scripts/set-cloudflare-env.ps1
./scripts/cloudflare-dns.ps1
```

اسکریپت اول Token را با ورودی خصوصی می‌گیرد؛ مقدار را در چت نفرستید. متغیرها فقط در همان نشست PowerShell موجودند. دستور دوم طرح DNS را نشان می‌دهد. پس از بررسی طرح، `./scripts/cloudflare-dns.ps1 -Apply` رکوردهای غایب را می‌سازد و رکورد متعارض موجود را جایگزین نمی‌کند.

تنظیم عمومی در `deployment/nginx-public.conf` و روی سرور در `/etc/nginx/sites-available/vyrn-public` قرار دارد. Caddy اجرا نشده چون Nginx قبلی پورت‌های ۸۰ و ۴۴۳ را دارد. API عمومی مسیرهای `/v1/admin` و `/v1/admin/*` و `/metrics` را با ۴۰۴ مسدود می‌کند. APK نباید برای دورزدن TLS به IP خام یا HTTP عمومی تغییر کند.

## ۹. رفع مشکل سریع

| نشانه | اقدام |
|---|---|
| پنل باز نمی‌شود | تونل SSH باز و پورت محلی آزاد باشد؛ دستور `dc ps` و سلامت را بررسی کنید |
| `Permission denied (publickey)` | مسیر کلید، کاربر root و پورت ۳۹۳۹ را بررسی کنید؛ کلید دیگری جایگزین نکنید |
| هشدار تغییر Host Key | توقف اتصال و تطبیق مستقل با کنسول Provider؛ known_hosts را کورکورانه حذف نکنید |
| کد TOTP رد می‌شود | ساعت خودکار گوشی، کلید ثبت‌شده و کد بازه بعدی را بررسی کنید |
| ورود درست است ولی پنل خطا دارد | دوباره ورود/TOTP؛ سپس سلامت Core و لاگ بررسی شود |
| APK وصل نمی‌شود | سلامت HTTPS، اینترنت دستگاه، نشانی API داخل Build و سازگاری نسخه را بررسی کنید |
| فضای دیسک کم است | حجم لاگ و رسانه بررسی شود؛ Volume دیتابیس یا فایل‌های کاربران را دستی حذف نکنید |

## ۱۰. نتیجه تست تحویل

ورود SSH با کلید اختصاصی، سلامت دو کانتینر، ورود حساب اونر، TOTP، خواندن داشبورد/کاربران/گروه‌ها/دعوت‌ها/گزارش فعالیت، ساخت و لغو دعوت آزمایشی، و خروج نشست آزمایشی روی همین VPS موفق بوده‌اند. پنل از تونل محلی HTTP ۲۰۰ می‌دهد. DNS/TLS عمومی، سلامت چهار دامنه API و مسدودبودن مدیریت/metrics از بیرون، ورود و خروج HTTPS و تمدید آزمایشی گواهی موفق بوده‌اند. اطلاعات ورود در سورس یا Git ذخیره نشده‌اند. تست مرورگر با حساب اونر، ریبوت کامل، جریان کامل APK تولید، Release Android، تماس و Backup خارجی هنوز تأیید نشده‌اند.
