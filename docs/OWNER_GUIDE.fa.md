# نصب و استفاده از VYRN

VYRN سورس عمومی دارد، اما هنوز نسخهٔ Stable پشتیبانی‌شده نیست. برای معرفی و آزمایش مناسب است؛ پیش از سپردن دادهٔ مهم، محدودیت‌ها و روش بازیابی را بررسی کنید. این پروژه مستقل از تلگرام است؛ حساب تلگرام شما وارد این شبکه نمی‌شود.

## راه‌اندازی روی سرور خودتان

مسیر ساده: پس از دریافت سورس روی Ubuntu24.04، دستور `sudo bash setup.sh --lang fa` را اجرا و گزینهٔ۱ را انتخاب کنید. دامنه، IP و اطلاعات مدیر را مرحله‌به‌مرحله می‌گیرد. [راهنمای کامل پنل ترمینالی](SETUP_WIZARD.md). مراحل زیر مرجع نصب دستی هستند.

۱. یک سرور Ubuntu24.04 با دامنهٔ خودتان آماده کنید. بودجهٔ اولیه برای آزمایش کوچک:۴ گیگابایت رم،۲ هسته و۴۰ گیگابایت دیسک؛ ظرفیت واقعی به بار و فایل‌ها بستگی دارد. فضای بیشتر برای رسانه و بکاپ لازم است.

۲. مراحل و دستورهای دقیق [راهنمای نصب](DEPLOYMENT.md) را به‌ترتیب انجام دهید: نصب Docker، دریافت سورس، تنظیم DNS، ساخت فایل محرمانه، ساخت Backend و راه‌اندازی PostgreSQL.

۳. دامنهٔ نمونهٔ `vyrn.example.com` را با دامنهٔ خودتان عوض کنید. آدرس‌های api،ws،media،push،admin وupdates باید به سرور برسند. برای مدیریت فقط IP یا VPN خودتان را در `VYRN_ADMIN_ALLOWED_CIDRS` مجاز کنید. آدرس اصلی سایت فعلاً وب‌مسنجر نیست.

۴. فایل `/etc/vyrn/runtime.env` روی سرور نگهداری می‌شود و نباید وارد Git شود. رمز دیتابیس و Secret برنامهٔ Authenticator در مرحلهٔ تنظیم تولید می‌شوند. Secret را به‌صورت حساب زمان‌محور در Authenticator وارد کنید؛ آن را در کادر کد شش‌رقمی پنل ننویسید.

۵. دستور bootstrap را فقط یک بار روی دیتابیس خالی اجرا کنید. ایمیل و رمز مدیر را خودتان انتخاب می‌کنید؛ رمز عمومی یا پیش‌فرض وجود ندارد. سپس Core و Caddy را روشن کنید و سالم‌بودن HTTPS را بررسی کنید.

۶. اپ را روی ویندوز با PowerShell7 برای آدرس API خودتان بسازید. فایل APK پروژه به سرور پروژه وصل می‌شود؛ برای سرور مستقل باید Build مخصوص خودتان داشته باشید. کلید امضای نهایی را روی کامپیوتر امن، خارج از Git و VPS نگه دارید.

## ورود به پنل

آدرس `https://admin.YOUR_SERVICE_DOMAIN` را از IP مجاز باز کنید. ابتدا ایمیل و رمز bootstrap، سپس کد فعلی شش‌رقمی Authenticator را وارد کنید. ساعت دستگاه و سرور باید درست باشد. کد مصرف‌شده در همان بازه دوباره قبول نمی‌شود؛ منتظر کد بعدی بمانید. دسترسی مدیریتی پس از۵ دقیقه تأیید مجدد می‌خواهد.

## اضافه‌کردن کاربر

- در پنل، «دعوت‌ها» را باز کنید؛ تعداد استفاده و اعتبار کوتاه مشخص کنید.
- «ساخت دعوت» را بزنید و کد نمایش‌داده‌شده را همان موقع ذخیره کنید؛ متن کد بعداً قابل بازیابی نیست.
- کد و APK مربوط به همان سرور را خصوصی به فرد بدهید.
- فرد در اپ ثبت‌نام می‌کند: ایمیل، رمز، نام نمایشی و کد دعوت.
- کد بازیابی را در محل امن نگه می‌دارد. ورودهای بعدی با ایمیل و رمز است؛ نام عمومی جای ایمیل ورود نیست.
- حساب و دعوت هر سرور فقط برای همان سرور است. فدراسیون یا انتقال خودکار حساب وجود ندارد.

دعوت اولیهٔ bootstrap برای استفادهٔ روزانه نیست. از پنل دعوت محدود بسازید؛ می‌توانید آن را لغو کنید. سرویس ایمیل تأیید یا ارسال خودکار رمز در این نصب وجود ندارد.

## اختیارات مدیر

| بخش | امکانات فعلی |
| --- | --- |
| نمای کلی | آمار کاربران، نشست‌ها، گروه‌ها و فضای مصرفی |
| کاربران | مسدود/فعال‌کردن، بازنشانی رمز، لغو نشست‌های کاربران دیگر |
| دعوت‌ها | ایجاد و لغو کد دعوت |
| گروه‌ها | مشاهدهٔ گروه‌ها و تعداد اعضا |
| گزارش فعالیت | رویدادهای مدیریتی |
| زبان | فارسی و انگلیسی |

بازنشانی رمز، نشست‌ها را لغو می‌کند؛ کلیدهای رمزنگاری ازدست‌رفته را برنمی‌گرداند. پنل ابزار خواندن متن پیام خصوصی نیست. پیام گروهی و اطلاعات جانبی شبکه را هم‌ارز پیام خصوصی رمزنگاری‌شده فرض نکنید.

## استفاده و نگهداری

ابتدا با دو حساب آزمایشی، ثبت‌نام، پیام، فایل و نیازهای واقعی خود را بررسی کنید. پیام صوتی وجود دارد؛ تماس صوتی/تصویری فعلاً غیرفعال است. بات، استوری و کانال پشتیبانی نمی‌شوند. همهٔ صفحه‌های رابط تلگرام هنوز به قابلیت متناظر متصل نیستند.

پیش‌نویس متن روی همان دستگاه ذخیره می‌شود؛ همگام‌سازی ابری پیش‌نویس وجود ندارد. دستگاه فیزیکی، رفتار پس‌زمینه و نسخهٔ Release هنوز پذیرش کامل ندارند.

از دیتابیس، فایل‌های رسانه و تنظیمات، بکاپ رمزگذاری‌شده در مقصدی خارج از سرور بگیرید و بازیابی را واقعاً تمرین کنید. بکاپ روی همان VPS قابل اتکا برای خرابی کامل نیست. دستور `down -v` می‌تواند داده‌ها را حذف کند؛ برای رفع مشکل ورود از آن استفاده نکنید.
