# گزارش کار و نحوهٔ عملکرد VYRN

VYRN یک پروژهٔ پیام‌رسان مستقل با سورس عمومی است: اپ اندروید، سرور اختصاصی و پنل مدیریت دارد. صاحب هر نصب، سرور و حساب‌های همان شبکه را مدیریت می‌کند. این پروژه به حساب‌ها و سرورهای تلگرام متصل نمی‌شود و بین نصب‌های مختلف هم فدراسیون ندارد.

رابط اندروید از سورس مشخص و پین‌شدهٔ Telegram گرفته شده است. بخش اختصاصی VYRN، اتصال این رابط به API مستقل، Backend، ورود ایمیلی، برند، ذخیره‌سازی و ابزارهای مدیریت و استقرار است؛ رابط تلگرام را از صفر نساخته‌ایم.

## ۱. اجزای پروژه

| جزء | کار آن |
| --- | --- |
| اپ اندروید | ثبت‌نام، ورود، نمایش چت، پیام و رسانه؛ نگهداری اطلاعات محلی |
| لایهٔ اتصال VYRN | تبدیل درخواست‌های رابط تلگرام به درخواست‌های سرور مستقل |
| VYRN Core | احراز هویت، مجوزها، پیام‌ها، گروه‌ها، فایل‌ها و رویدادها |
| PostgreSQL | حساب‌ها، نشست‌ها، عضویت، اطلاعات پیام و داده‌های سرور |
| فضای رسانه | نگهداری فایل‌ها با کنترل دسترسی و شناسهٔ تولیدشده |
| VYRN Control | پنل فارسی/انگلیسی مدیر |
| Caddy و Docker Compose | HTTPS و اجرای سرویس‌ها در نصب مستقل |

اپ از مسیر HTTPS به سرور می‌رسد. درخواست‌های عادی از API و تغییرات گفتگو از رویدادهای WebSocket/همگام‌سازی دریافت می‌شوند. کلیدهای دستگاه و بخشی از داده‌های محلی روی خود دستگاه می‌مانند؛ بکاپ سرور جای همهٔ داده‌های دستگاه را نمی‌گیرد.

## ۲. ساخت حساب و ورود

۱. صاحب سرور یک مدیر اولیه با ایمیل و رمز انتخابی خودش می‌سازد؛ رمز پیش‌فرض عمومی وجود ندارد.

۲. مدیر با ایمیل و رمز وارد Control می‌شود و کد شش‌رقمی Authenticator را می‌دهد. دسترسی مدیریتی زمان محدود دارد و تأیید مجدد می‌خواهد.

۳. مدیر کد دعوت با تعداد استفاده و اعتبار مشخص تولید می‌کند. متن کد هنگام ساخت نمایش داده می‌شود؛ سرور هش آن را نگه می‌دارد.

۴. کاربر با اپ مربوط به همان سرور، ایمیل، رمز، نام نمایشی و کد دعوت ثبت‌نام می‌کند. کد بازیابی باید خصوصی ذخیره شود. ورودهای بعدی با ایمیل و رمز است؛ نام عمومی جای ایمیل ورود نیست.

۵. سرور نشست دستگاه را صادر می‌کند. توکن‌های اپ با کمک Android Keystore محافظت می‌شوند؛ تمدید و لغو نشست در Backend کنترل می‌شود. سرویس ایمیل تأیید/ارسال رمز در این نصب وجود ندارد.

## ۳. وقتی کاربر پیام می‌فرستد

- اپ برای پیام یک شناسهٔ پایدار در صف محلی نگه می‌دارد.
- درخواست از اتصال امن به Core می‌رسد؛ سرور نشست، عضویت و اجازهٔ عملیات را بررسی می‌کند.
- تغییر مجاز در تراکنش ثبت می‌شود و رویداد آن در مسیر همگام‌سازی قرار می‌گیرد.
- دستگاه مقابل رویداد را می‌گیرد، دادهٔ مجاز را دریافت می‌کند و گفتگو را به‌روزرسانی می‌کند.
- اگر پاسخ به‌خاطر قطع اتصال نرسد، تکرار همان درخواست با شناسهٔ یکسان برای جلوگیری از ساخت پیام تکراری طراحی شده است.

صف محلی و مسیر بازیابی برای قطع شبکه و توقف پردازش تست‌های هدفمند دارند. این طراحی به‌معنای تضمین تحویل در تمام شرایط، پس‌زمینهٔ همهٔ گوشی‌ها یا هر نوع خرابی نیست.

## ۴. تفاوت پیام خصوصی و گروه

مسیرهای پیام خصوصی با کتابخانهٔ Signal، کلیدهای دستگاه و ارسال دادهٔ رمز‌شده یکپارچه شده‌اند. بخشی از وضعیت رمزنگاری و دادهٔ خصوصی محلی هم روی دستگاه محافظت می‌شود. پنل مدیر ابزار خواندن متن پیام خصوصی نیست.

پیام گروهی و اطلاعات جانبی شبکه را نباید هم‌ارز پیام خصوصی رمزنگاری‌شده فرض کرد. مدیر زیرساخت به داده‌ها و اطلاعاتی که سرور واقعاً نگه می‌دارد دسترسی زیرساختی دارد. استفاده از Signal هم جای بررسی امنیتی مستقل و پذیرش کامل چرخهٔ کلیدها، رسانه و دستگاه‌ها را نمی‌گیرد.

بازنشانی رمز ورود، کلید رمزنگاری ازدست‌رفتهٔ دستگاه را دوباره نمی‌سازد.

## ۵. امکانات پیاده‌سازی‌شده

| بخش | مسیرهای موجود |
| --- | --- |
| گفتگو | پیام خصوصی و گروهی، تاریخچه، ویرایش، حذف، واکنش و رسید خواندن |
| گروه | ساخت گروه، دعوت عضو، تغییر نام با تأیید سرور و نقش‌های پایه |
| رسانه | مسیرهای فایل، عکس و پیام صوتی با محدودیت اندازه و فضا |
| دادهٔ محلی | صف پایدار، جست‌وجو و پیش‌نویس متن؛ پیش‌نویس خصوصی محافظت‌شده |
| حساب | دعوت، ورود، بازیابی و مدیریت نشست دستگاه |
| مدیریت | آمار، مسدودسازی، تغییر رمز، لغو نشست، دعوت و گزارش فعالیت |
| عملیات | Compose، HTTPS، ابزار بکاپ رمزگذاری‌شده و بررسی بازیابی |

وجود این مسیرها یعنی کد و تست‌های مشخص برای آن‌ها وجود دارد؛ همهٔ صفحه‌ها و سناریوها پذیرش کامل ندارند. پیش‌نویس ابری بین دستگاه‌ها همگام نمی‌شود.

## ۶. نصب مستقل و دادن دسترسی

صاحب نصب، دامنه و DNS خودش را تنظیم می‌کند؛ اطلاعات محرمانه را بیرون Git قرار می‌دهد؛ PostgreSQL و Core و پراکسی HTTPS را راه می‌اندازد؛ سپس مدیر اولیه را می‌سازد.

اپ باید برای API همان نصب Build شود. APK آمادهٔ پروژه به سرور پروژه اشاره می‌کند و در صفحهٔ ورود گزینهٔ تعویض سرور ندارد. حساب، دعوت و دادهٔ یک نصب در نصب دیگر معتبر نیستند.

بعد از آماده‌شدن، مدیر APK متناظر و دعوت محدود را خصوصی به کاربر می‌دهد. برای نصب واقعی باید بکاپ رمزگذاری‌شدهٔ خارج از سرور و بازیابی آن هم آماده و تمرین شود. کپی روی همان VPS برای ازدست‌رفتن سرور قابل اتکا نیست.

## ۷. چه چیزهایی بررسی شده‌اند؟

در اجرای ثبت‌شدهٔ ۲۰ اکتبر ۲۰۲۶، مجموع۴۳۸ بررسی اندروید در مسیرهای ورود، یکپارچگی/مهاجرت صف، شبکه و رمزنگاری Signal و مدیریت نشست موفق بوده‌اند. این عدد تعداد بررسی‌های ثبت‌شده است، نه۴۳۸ سفر کاربری مستقل یا تضمین بی‌نقص‌بودن اپ.

دو تلاش تازهٔ تست دوکلاینتی پس از ثبت‌نام، با کرش شبیه‌ساز میزبان متوقف شدند؛ ارسال/ویرایش/حذف/بازیابی آن اجراها تأیید نشده است. گزارش‌های قدیمی‌تر به‌جای نتیجهٔ تازه استفاده نشده‌اند.

بررسی‌های گیت‌هاب برای پاکیزگی مخزن، اسکریپت‌ها، تنظیمات دامنهٔ سفارشی، تست‌های Backend/PostgreSQL همراه تشخیص هم‌زمانی، آسیب‌پذیری‌های قابل دسترس و ساخت کانتینر اجرا می‌شوند. نتیجه باید برای همان کامیت بررسی شود.

## ۸. کارهای انجام‌شده برای ارائهٔ عمومی

- یادداشت‌های داخلی و گزارش‌های تکراری حذف یا خلاصه شده‌اند؛ کد، تست و مجوزها حفظ شده‌اند.
- README به صفحهٔ معرفی، مسیر نصب و راهنمای سریع استفاده تبدیل شده است.
- نصب با دامنه و IP انتخابی افراد مستند و تنظیمات اصلی قابل تغییر شده‌اند.
- راهنمای فارسی/انگلیسی، معماری، امنیت، امضا، بکاپ و متن معرفی رزومه آماده‌اند.
- معرفی و موضوعات گیت‌هاب و مسیر گزارش محرمانهٔ آسیب‌پذیری تنظیم شده‌اند.

این تغییرات، صفحه و مستندات عمومی را آماده می‌کنند؛ به‌تنهایی به‌معنای تکمیل همهٔ قابلیت‌های اپ نیستند.

## ۹. وضعیت تحویل و کارهای باقی‌مانده

**وضعیت فعلی: Development Preview با سورس عمومی.** نسخهٔ Stable اندروید هنوز منتشر نشده است.

امضای نهایی، تست روی خودِ Release بهینه‌شده، پذیرش مطمئن دوکلاینتی، پوشش بیشتر پس‌زمینه/چرخهٔ حساب/رسانه، سازگاری دستگاه‌های فیزیکی و بررسی نهایی سورس و مجوزهای باینری باقی مانده‌اند. بکاپ خارجی هم به مقصد و تمرین بازیابی هر نصب وابسته است.

تماس صوتی و تصویری، بات، استوری، کانال و تماس گروهی فعلاً در دسترس نیستند. **پیام صوتی با تماس صوتی فرق دارد.**

برای رزومه، پروژه را «پیام‌رسان قابل میزبانی شخصی با کلاینت مشتق از تلگرام و Backend اختصاصی» معرفی کنید. ادعای رابط کاملاً اصیل، امنیت ممیزی‌شده یا نسخهٔ Stable کامل، با وضعیت فعلی سازگار نیست.
